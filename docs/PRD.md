# PRD — 工业安防监测系统 产品需求文档

## 1. 产品概述

### 1.1 产品名称
工业安防监测系统 (Industrial Security Monitoring System)

### 1.2 产品定义
一个基于计算机视觉的实时工业安防监测 Web 系统。通过智能摄像头采集视频流，利用 YOLO 深度学习模型实时识别施工场景中的安全违规行为（未佩戴安全帽、未穿反光衣）和人员摔倒事件，并在 Web 界面上实时展示检测结果、统计数据和告警信息。

### 1.3 目标用户

| 用户角色 | 描述 |
|---------|------|
| **课程/毕业设计评审老师** | 验收项目功能、评估技术实现质量 |
| **项目演示观众** | 在答辩/展示现场观看实时监测效果 |
| **（远期）工地安全管理员** | 在实际工业场景中监控作业人员安全状况 |

### 1.4 项目背景
- 三人小组协作项目
- 用户（你）负责全部软件工程：推理引擎、Web 服务、前端界面、系统集成
- 队友负责：安全帽/反光衣检测数据集收集与 YOLO 模型训练
- 硬件：全志 H618 智能摄像头（嵌入式 Linux 开发板）

## 2. 功能需求

### 2.1 核心功能（P0 — 必须实现）

#### F1: 实时视频采集
- 从 H618 智能摄像头通过 WiFi 局域网获取 MJPEG 视频流
- 摄像头端 Flask 推流作为黑盒，不做修改
- PC 端通过 OpenCV `cv2.VideoCapture(MJPEG_URL)` 拉流

#### F2: 安全装备检测
- 实时检测画面中的人体安全装备状态（方案 A，人体框带属性）：
  - `person_helmet` — 佩戴安全帽的人
  - `person_no_helmet` — 未佩戴安全帽的人
  - `person_vest` — 穿着反光衣的人
  - `person_no_vest` — 未穿反光衣的人
- 在视频画面上绘制检测边界框：
  - 合规（佩戴/穿着）→ 绿色框 + HELMET / VEST 标签
  - 违规（未佩戴/未穿着）→ 红色框 + NO-HELMET / NO-VEST 标签
- 使用队友训练的 YOLO 模型（`helmet_vest.pt`）
- 在队友模型交付前，使用 YOLOv8n 官方预训练模型作为占位

**模型输出契约（需与队友明确对齐）：**

| 方案 | 模型输出 | 统计方式 | 优先级 |
|------|---------|---------|--------|
| **方案 A（推荐）** | 人体框 + 属性：`person_helmet`, `person_no_helmet`, `person_vest`, `person_no_vest` | 直接计数每个类别框数 = 人数 | 🥇 |
| **方案 B** | 人体框 + 装备框分离，模型同时输出 person bbox 和 helmet/vest bbox | 对每个装备框做 IoU 匹配到最近人体框，匹配失败则丢弃 | 🥈 |
| **方案 C** | 仅装备框（不区分人） | 数 no-helmet 框 != 数人数，需额外做 NMS + 聚类，复杂度高 | 🥉 |

> **约定**：优先争取方案 A。如果队友只能交付方案 B 或 C，需在阶段 8 额外实现人-装备匹配逻辑，工期需相应增加。

#### F3: 人体姿态估计与摔倒检测
- 使用 YOLOv8n-pose 官方预训练模型检测人体 17 个关键点
- 基于关键点几何关系判断摔倒（不需要额外训练模型），使用多特征综合判断：

**摔倒判断规则（多条件 AND）：**

| 条件 | 规则 | 说明 |
|------|------|------|
| 躯干倾角 | `躯干高度(肩-髋) / 身体高度(肩-踝) < 0.25` | 身体接近水平 |
| 人体宽高比 | `bbox_width / bbox_height > 1.2` | 摔倒时人体宽度 > 高度 |
| 关键点置信度 | 肩、髋、踝 6 个关键点置信度均 ≥ 0.5 | 防止遮挡误判 |
| 时序确认（触发） | 连续 ≥ 3 帧判定为摔倒才触发 | 防止单帧抖动误报 |
| 时序确认（解除） | 连续 ≥ 5 帧判定为正常才解除 | 防止摔倒恢复过程中的抖动 |

- 摔倒人物在画面上用特殊标记（红色 "⚠ FALL" 文字 + 闪烁边框）

#### F4: 实时 Web 监控界面
- 浏览器中实时显示带检测标注的视频画面
- 统计面板实时更新：
  - 画面总人数
  - 未佩戴安全帽人数
  - 未穿反光衣人数
  - 摔倒检测状态（是否触发）
- 摔倒触发时，视频画面上叠加 "⚠ 摔倒警告" 字符

#### F5: 告警音频
- 告警音 1（alarm1.mp3）：检测到未佩戴安全帽 或 未穿反光衣时触发
- 告警音 2（alarm2.mp3）：检测到摔倒时触发
- 音频从 PC 扬声器（非摄像头）发出，使用 Python `pygame` 播放

**告警状态机（防止帧级抖动导致反复开停）：**

```
                连续 N 帧检测到违规
  [静默] ──────────────────────────→ [播放中]
                                          │
                连续 M 帧违规消失          │
  [静默] ←────────────────────────── [播放中]
```

| 参数 | 值 | 说明 |
|------|-----|------|
| 触发阈值 | 连续 3 帧检测到违规 | 防止单帧误检触发告警 |
| 解除阈值 | 连续 5 帧违规消失 | 防止告警反复开停 |
| 音频幂等 | `play()` 调用时若已在播放则跳过 | 避免重复触发导致声音叠加 |

- 告警存在期间**循环播放**
- 告警解除后停止播放

#### F6: 实时统计推送
- 后端通过 WebSocket 向前端实时推送统计数据
- 推送频率：5-10 Hz（统计面板不需要逐帧更新，降低前端渲染压力）
- 视频流仍按推理帧率输出 MJPEG（视频和统计分频推送）
- 推送内容：总人数、违规人数、摔倒状态、时间戳

## 4. 非功能需求

### 4.1 性能
- 推理帧率目标：**8-15 FPS**（CPU 推理，同时运行检测 + 姿态两个模型）
- 视频流延迟：≤ 3 秒（摄像头 → PC → 浏览器，含推理耗时）
- WebSocket 推送延迟：≤ 200ms
- 优化策略（CPU 场景下保证可用帧率）：
  - 视频帧缩放到 640x480 输入模型
  - 姿态估计隔帧检测（每 2-3 帧跑一次，检测模型每帧都跑）
  - 视频 MJPEG 推流和 WebSocket 统计分频推送
  - JPEG 编码质量降低到 60-70（减少带宽压力）

### 4.2 可靠性
- 摄像头断连时自动重试连接，界面显示 "摄像头连接中..."
- 模型文件缺失时给出明确错误提示
- 单个模型推理失败不影响整体循环（跳过该帧）

### 4.3 可用性
- 一键启动：运行 `python main.py` 启动全部服务
- 浏览器访问 `http://localhost:8000` 即可查看
- 无需额外安装数据库或中间件

### 4.4 兼容性
- 操作系统：Windows 10/11
- 浏览器：Chrome / Edge（最新两个大版本）
- Python 版本：3.10+

## 5. 约束与假设

### 5.1 约束
- CPU 推理（用户电脑无 NVIDIA GPU）
- 单摄像头输入
- 摄像头和 PC 必须在同一 WiFi 局域网
- 摄像头 MJPEG 推流地址需在 config.py 中手动配置

### 5.2 假设
- 摄像头已正确配置并推流（黑盒可用）
- 队友交付的模型文件为 Ultralytics YOLO 标准 `.pt` 格式
- 模型类别名为 `person_helmet`, `person_no_helmet`, `person_vest`, `person_no_vest`（方案 A，人体框带属性）；如队友只能交付 `helmet`/`no-helmet`/`vest`/`no-vest` 装备框，则为方案 B/C，需额外人-装备匹配逻辑
- 画面中同时出现的人数 ≤ 20 人
- 室内/半室内演示环境，光照条件基本稳定

## 6. 术语表

| 术语 | 说明 |
|------|------|
| H618 | 全志 H618 SoC，Cortex-A53 架构，摄像头主控芯片 |
| MJPEG | Motion JPEG，一种视频流格式，每帧为独立 JPEG 图片 |
| YOLO | You Only Look Once，目标检测算法 |
| YOLOv8-pose | YOLOv8 的姿态估计变体，输出人体 17 个关键点 |
| COCO 关键点 | 标准人体 17 点标注格式（鼻、眼、耳、肩、肘、腕、髋、膝、踝） |
| FastAPI | Python 异步 Web 框架 |
| WebSocket | 全双工实时通信协议 |
| pygame | Python 音频/游戏库，本项目仅用其音频播放功能 |
